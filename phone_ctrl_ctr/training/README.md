# FunctionGemma voice command training

Fine-tune **google/functiongemma-270m-it** to turn an English speech transcript into a function call for Phone Control. This package trains the text router. Speech recognition, microphone capture and live inference are not connected to the phone app yet. The existing Voice screen still triggers Wispr.

## Included

- `train.py`: full parameter BF16 training with assistant-output-only loss, dynamic padding, SDPA, gradient checkpointing, checkpoint resume and DDP through `torchrun`.
- `train_h200.slurm`: editable two-node, eight-H200-per-node launch example.
- `data/train.jsonl`, `validation.jsonl`, `test.jsonl`: **1,402 / 322 / 322** examples, generated by `build_data.py`.
- `data/tools.json`: 12 function schemas. Each data row contains the transcript, expected function and expected companion command packet. Tools are stored once and inserted into every prompt at tokenization time.
- `functions.py`: shared schema validation, FunctionGemma output parser and command adapter. The adapter returns packets without executing them.
- `evaluate.py`: deterministic inference and held-out evaluation of syntax, function name, exact arguments, per-function accuracy and action errors on no-action requests.

## H200 setup

Use Linux, Python 3.11 or 3.12, and your cluster's CUDA-enabled PyTorch **>=2.6,<3** environment. Check its CUDA driver compatibility with your cluster administrator. A single H200 has ample capacity for this 270M model; multiple nodes are supported but may add overhead for this small corpus.

From the project root:

```bash
python -m venv --system-site-packages .venv
source .venv/bin/activate
python -m pip install -r training/requirements.txt
python -c 'import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))'
```

Accept the [FunctionGemma model license](https://huggingface.co/google/functiongemma-270m-it) yourself and authenticate with `hf auth login`. On clusters with blocked compute-node internet, download the model on a login node to a shared cache first:

```bash
hf download google/functiongemma-270m-it
python training/build_data.py
python training/train.py --check-data
python training/train.py --check-tokenization
```

`--check-tokenization` downloads only the tokenizer and verifies the real chat template, prefix masking and sequence lengths. Examples exceeding `--max-length` cause a clear error instead of losing targets to truncation. The default is 4,096 tokens including all tool definitions.

### First run: one H200

```bash
# Validate the actual CUDA stack and save/load path before a full run.
torchrun --standalone --nproc-per-node=1 training/train.py \
  --output training/runs/smoke --max-steps 2 --batch-size 1 --grad-accum 1

torchrun --standalone --nproc-per-node=1 training/train.py \
  --output training/runs/phone-command-v1 --batch-size 4 --grad-accum 4
```

### One node, eight H200s

```bash
torchrun --standalone --nproc-per-node=8 training/train.py \
  --output training/runs/phone-command-8gpu --batch-size 2 --grad-accum 1
```

Global batch size = GPUs × batch size × gradient accumulation. These two full-run examples both use a global batch of 16. Increase the per-device batch only after observing memory usage and quality. DDP assigns one complete model per GPU; `device_map="auto"` is deliberately not used.

### Multiple nodes through Slurm

Edit `training/train_h200.slurm` to match the GPU count, partition, account and wall time your cluster uses. The example requests 2 nodes × 8 GPUs and uses a global batch of 32. The project, Python environment, model cache and output directory must be shared across nodes. Slurm must provide each node access to all eight allocated GPUs.

```bash
sbatch --partition=YOUR_H200_PARTITION --account=YOUR_ACCOUNT training/train_h200.slurm
```

For reproducibility, pass `--revision HUB_COMMIT_HASH` instead of the default `main`. Archive `pip freeze`, the Slurm log, `run.json` and `data/manifest.json`. Do not run two jobs into the same output directory. Training refuses a nonempty output unless resuming:

```bash
torchrun --standalone --nproc-per-node=8 training/train.py \
  --output training/runs/phone-command-8gpu --batch-size 2 --grad-accum 1 \
  --resume training/runs/phone-command-8gpu/checkpoint-100
```

Use an actual checkpoint directory produced by your run and keep the original batch settings. The best validation-loss checkpoint is exported as `OUTPUT/final`, including tokenizer and tool schema. No Hub uploads or external experiment logging are enabled.

## Examples and outputs

| Transcript | Function | Companion packet |
| --- | --- | --- |
| Open Chrome | `launch_app(app="chrome")` | `{"type":"launch","app":"chrome"}` |
| Set volume to fifty percent | `set_volume(percent=50)` | `{"type":"volume","value":50}` |
| Set brightness to 25 percent | `set_brightness(percent=25)` | `{"type":"brightness","value":25}` |
| Next window | `desktop_action(action="nextWindow")` | `{"type":"gesture","name":"nextWindow"}` |
| Next desktop | `desktop_action(action="nextDesktop")` | `{"type":"gesture","name":"nextDesktop"}` |
| Next song | `media_control(action="next")` | `{"type":"media","action":"next"}` |
| Toggle playback | `media_control(action="playPause")` | `{"type":"media","action":"playPause"}` |
| Right click | `click_mouse(button="right")` | `{"type":"click","button":"right"}` |
| Scroll down 3 steps | `scroll_mouse(direction="down",steps=3)` | `{"type":"scroll","dx":0,"dy":-360}` |
| Zoom in | `zoom_view(direction="in")` | `{"type":"zoom","delta":120}` |
| List my open windows | `list_windows()` | `{"type":"windows"}` |
| Check the current volume | `get_state()` | `{"type":"state"}` |
| Toggle hands free dictation | `toggle_dictation()` | `{"type":"doubleClick","button":"x1"}` |
| Make it louder | `no_action(reason="ambiguous")` | No packet; ask for an absolute percentage |
| Don't open Chrome | `no_action(reason="cancelled")` | No packet |

The six apps match the current companion allowlist: Chrome, VS Code, ChatGPT, Spotify, File Explorer and Command Prompt. Desktop actions also include Task View, previous window/desktop, show desktop, Windows Search and notifications. Media supports play/pause toggle, next, previous and stop. Windows decides which media session handles its media keys; the button does not claim to know the current playback state.

The router supports **one command per utterance**. Requests with multiple actions, unrecognized apps, arbitrary shell commands, named-window focus without a real window ID, relative settings without current state, and exact play/pause or dictation on/off requests without state are trained to return `no_action`. These choices match functions the companion can actually perform. Add context and matching handlers/examples before teaching new operations.

## Evaluate and try transcripts

```bash
# Compare base and fine-tuned models on identical held-out examples.
python training/evaluate.py --model google/functiongemma-270m-it --report training/base-evaluation.json
python training/evaluate.py --model training/runs/phone-command-v1/final --report training/tuned-evaluation.json
python training/evaluate.py --model training/runs/phone-command-v1/final --text "open spotify"
```

Inference prints the raw FunctionGemma response, validated function and companion JSON. Malformed outputs, extra calls, unknown arguments and out-of-range numbers produce no command. Nothing is sent to Windows. Future integration is: speech-to-text → router → validation/adapter → existing authenticated companion connection. Keep runtime validation even after fine-tuning; training accuracy is not an execution guarantee.

## Data quality and extending the dataset

This is a **synthetic starter corpus**, not a measured production model. Split boundaries hold out phrasing families; argument values and supported intents deliberately recur across splits. Numeric settings create many more rows than other functions, so training repeats rare function examples to balance function exposure by default. Repetition does not add language diversity; disable with `--no-balance-functions` for comparisons. Evaluation uses the original untouched validation/test distributions and reports macro per-function accuracy to reveal weak rare commands.

Collect your own transcribed commands, corrections, ASR mistakes and unsupported requests. Keep all variants from a speaker/session or paraphrase family in one split. Reserve an additional real voice test set. Start by improving weak functions and no-action recall rather than duplicating more numeric templates. Tune learning rate/epochs on validation; use test data only for final comparisons. For larger custom corpora, retain the JSONL row format and update the manifest; `--check-data` checks schema, packets and split separation.
